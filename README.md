# Systems Analysis & AI Development Learning

This repository is my learning environment for exploring how traditional
Systems Analysis and Design practices can be combined with AI-assisted
software development and vibe coding.

## Learning Objectives

- Learn Git and GitHub fundamentals
- Learn AI-assisted software development
- Experiment with vibe coding
- Explore requirements-driven AI development
- Understand how traditional Systems Analysis artifacts can guide AI agents
- Compare tools such as GitHub Copilot, Replit, Lovable, Cursor, and Gemini CLI

## Project Structure

The repository is organized around Systems Analysis and Design phases:

```text
planning/             Project scope, plans, and the system request
analysis/             Requirements, stories, and conceptual models
design/               System, architecture, data, and UI design
implementation/src/   Future application source code
testing/              Test plans, cases, and future automated tests
docs/                 General project and user documentation
requirements/         Existing system request
```

The existing [system request](requirements/system-request.md) remains in its
original location. An application-specific system request can later be
developed under `planning/`.

The planned `analysis/requirements.md` will be the authoritative source for
approved application requirements and business rules. It has not yet been
created or approved. Stories, models, designs, and tests should trace back to
requirements; resolve conflicts and open questions in the requirements before
implementation.

## Guiding Principle

AI should implement well-defined requirements rather than replace
requirements analysis.
